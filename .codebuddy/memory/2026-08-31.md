## FreeMarker 踩坑（两个都已修）
1. **`#if !field.nullAble` 报 "Expected a boolean, but this has evaluated to a string"**
   - 根因：`Field.nullAble` 是 `String`，DbUtil 里 `setNullAble(String.valueOf(...))` 存的是 `"true"`/`"false"` 字符串，FreeMarker 无法当布尔用。
   - 修法：`Field.nullAble` 类型改为 `Boolean`，DbUtil 直接 `setNullAble("YES".equals(nullAble))`。
   - 教训：模板里要做布尔判断的字段，Java 侧必须用 boolean/Boolean，不能用字符串。
2. **生成的 java 文件中文乱码**（如 `銆?会员id銆戜笉鑿戒负绌?`）
   - 根因：`new FileWriter(file)` 固定用平台默认编码（Windows=GBK），而 ftl 是 UTF-8。
   - 修法：`FreemarkerUtil` 两处：
     - `cfg.setDefaultEncoding("UTF-8")`（读模板）
     - 输出用 `new BufferedWriter(new OutputStreamWriter(Files.newOutputStream(...), StandardCharsets.UTF_8))`（写文件），并用 try-with-resources。
   - 教训：**永远不要直接用 `FileWriter`/`FileReader`**，一律显式指定 `StandardCharsets.UTF_8`。

## Jackson 3.x 的包名（已实测澄清，勿再混淆）
- **只有 `core` / `databind` 迁到了 `tools.jackson.*`，注解包没有迁**。
  - `jackson-databind:3.1.5` 的官方 pom 注释：`<!-- 14-Jul-2022, tatu: Note! Annotations remain at Jackson 2.x group id -->` `<groupId>com.fasterxml.jackson.core</groupId>`。
  - `tools.jackson.core:jackson-annotations` **在中央仓库不存在**（下载报 absent）。
  - 实测 jar 内容：`tools/jackson/databind/annotation/JsonSerialize.class` 存在；`tools/jackson/annotation/JsonFormat.class` 不存在，只有 `com/fasterxml/jackson/annotation/JsonFormat.class`。
- 结论：`@JsonFormat` 的 import **永远是 `com.fasterxml.jackson.annotation.JsonFormat`**；`@JsonSerialize` 才是 `tools.jackson.databind.annotation.JsonSerialize`。项目里同一文件混用两个包名是正常的。

## saveReq.ftl 的三条生成规则（踩坑后确立）
1. **bigint(Long) 字段在 Req 里一律用 `String`** —— 雪花 ID 超过 JS 53 位精度，前后端必须字符串传递。
   - 直接按 `field.javaType` 映射成 `Long` 会破坏 `PassengerService` 的 `Long.parseLong(req.getId())`，导致 member 编译失败。
   - Domain/Resp 侧仍是 Long，靠 `@JsonSerialize(ToStringSerializer)` 转字符串。
2. **`id` 和 `memberId` 不加非空校验** —— id 由后端 `SnowUtil` 生成，memberId 由 `LoginMemberContext` 填充，都不由前端传入。加 `@NotNull` 会让新增请求被校验拦截。
3. **保留 Lombok `@Getter/@Setter/@ToString`**，不手写 getter/setter（原版 26 行，手写后膨胀到 126 行）。
- 另：`NotBlank` / `NotNull` 的 import 按需生成（先用 `<#assign>` 扫一遍 fieldList 判断），避免无用 import。
